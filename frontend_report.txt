4. RESPONSE SHAPE — UI vs. BACKEND CONTRACT
================================================================================

A. Shape the UI expects today (from server/services/ragEngine.js, wrapped by api.js in {success, data}):
   {
     success: true,
     data: {
       query:            string
       answer:           string
       trust_score:      number (15–98, never null)
       confidence_label: string ("High Confidence" | "Medium Confidence" | "Low Confidence")
       badge_title:      string
       badge_sub:        string
       color:            string (hex color)
       factors:          string[]
       sources:          [ { id, title, subtitle, tag, icon, details } ]
     }
   }

B. Shape from the FastAPI contract:
   {
     answer:           string
     trust_score:      number | null
     label:            "High" | "Medium" | "Low" | "Abstained" | "Unverified"
     score_type:       "support_only" | "combined" | null
     sources:          [ { source: string, section_number: string } ]
     abstained:        bool
     latency_seconds:  number
   }

C. Field-by-field differences:

   FIELD              UI EXPECTS                  CONTRACT PROVIDES           DIFF
   ────────────────── ─────────────────────────── ─────────────────────────── ──────────────────
   Wrapper            {success:true, data:{…}}    flat JSON object            UI reads result.data; contract has no wrapper
   answer             data.answer                 answer                      Same semantics; path differs due to wrapper
   trust_score        data.trust_score (number)   trust_score (number|null)   UI never handles null; falls back to 90 via || 90
   confidence_label   data.confidence_label       —                           MISSING from contract; UI derives display label from this
   label              —                           label                       UI does not read this field
   badge_title        data.badge_title            —                           MISSING from contract
   badge_sub          data.badge_sub              —                           MISSING from contract
   color              data.color                  —                           MISSING from contract
   factors            data.factors                —                           MISSING from contract
   score_type         —                           score_type                  UI does not consume this
   abstained          —                           abstained                   UI does not consume this
   latency_seconds    —                           latency_seconds             UI does not consume this
   sources            [{id,title,subtitle,        [{source,section_number}]   COMPLETELY DIFFERENT shape
                        tag,icon,details}]
   query              data.query                  —                           MISSING from contract
   Error response     HTTP non-ok → catch         503 + {detail}              UI checks response.ok but doesn't read detail; silently injects hardcoded answer

   SUMMARY: The UI will NOT work with the FastAPI backend as-is. At minimum:
   1. UI expects { success: true, data: { … } } wrapper — contract returns flat JSON.
   2. sources shape is totally different ({title,subtitle,tag,icon} vs {source,section_number}).
   3. UI uses confidence_label, badge_title, badge_sub, color, factors — none exist in contract.
   4. Contract fields label, score_type, abstained, latency_seconds are ignored by the UI.
   5. trust_score=null will render as 90% in the ring (silent fallback, misleading).
